# found-footy comprehensive audit — 2026-08-13

**Scope**: as-built Go rebuild (`rebuild/go`) two days before the 2026-08-15 La Liga
cutover. Synthesised from 99 verified findings across ten subsystems, cross-checked
against `schema.sql`, `decisions.md` (through 2026-08-13), the as-built ledgers, and
the shipped code. Builds on [`audit-2026-08-05.md`](./audit-2026-08-05.md); its still-open
items are carried in [§6](#6-carry-forward-from-2026-08-05).

**Method note**: findings were de-duplicated and re-ranked by real user-facing impact,
not by the reporting agent's local severity. Several P1s from the source set that
converge on one root cause were merged and promoted; several isolated P1s were held
at P2 because they only bite in failure states.

## 1. Executive summary

The Go build is **functionally complete through the V-phase**. Ingest, monitor/debounce,
discovery, the per-event Firefox fleet, download, vision, category-scoped dedup, persist,
ranking, and the Chi read API are all shipped and were live-validated on 2026-08-12. The
code is consistently healthier than the Python it replaces — the 2026-08-05 finding that
"the liability is documentation drift, not logic" still holds.

**It is not yet cutover-ready.** Five things block or derisk the cutover, in order:

1. **Two hot-path activities carry the exact #184 unsatisfiable-heartbeat bug.**
   `vision.ValidateClip` (`HeartbeatTimeout=1m`) and `discovery.SearchTweets`
   (`HeartbeatTimeout=30s`) both set a heartbeat timeout and emit **zero** `RecordHeartbeat`
   calls. Temporal kills each attempt at start+timeout regardless of the 2–3 min
   `StartToClose` budget. Under the multi-match load the new fleet produces, queued vision
   calls wait past 60s on the cap-4 joi semaphore → killed → retried → **positive-feedback
   retry storm on the exact bottleneck resource**, and fully-downloaded, hard-filter-passed
   clips are permanently dropped. #184 fixed this for the two video activities and missed
   these two. **This is the single highest-leverage speed-to-clip and clip-loss fix.**

2. **There is no schema migration path, and a fresh apply aborts on a stock Postgres image.**
   `schema.sql` applies only on a fresh dev volume or ephemeral testcontainer; `schema.go`
   defers migration to "future tooling" that does not exist. Schema edits silently no-op
   against a live DB — this has already bitten twice (2026-08-06 stale-DB, 2026-08-12 missing
   `superseded` enum). Separately, `CREATE EXTENSION vector` at `schema.sql:21` (for the
   never-written `tweet_intent` table) makes the whole schema abort on `postgres:16-alpine`;
   only `pgvector/pgvector:pg16` carries it. A cutover that forgets the pgvector image, or a
   schema tweak landed the day before cutover, fails silently or hard.

3. **The Firefox fleet has no orphan reaper and a state-blind cap.** All three release sites
   log "reaper will sweep" but **no reaper exists** (#183). Containers are `RestartPolicy:no`,
   `AutoRemove:false`, and the `MaxInstances=16` cap counts **stopped** containers via
   `ContainerList{All:true}`. Leaked instances self-amplify until every slot is consumed;
   provisioning then blocks the full 30s and errors — and there is **no fallback to the shared
   service** (the "falls back" comment is factually wrong), so affected goals go clip-less.
   Ship #183 before enabling the fleet in prod.

4. **Ingest partial-league refresh is destructive precisely at the launch target.** A single
   league's API blip during refresh does not abort — it `TRUNCATE`s and rewrites the cache
   with only the surviving leagues, stamps every row `refreshed_at=now`, and then skips
   refresh for 24h. The wiped league's fixtures are silently filtered out for a day. Total
   failure is safe; partial failure is destructive — an inverted, dangerous asymmetry,
   amplified by the summer season-rollover window when new-season `/teams` rosters are still
   empty.

5. **Real-time surfacing has no push path, and durability docs lie.** Core-NATS publish is
   fire-and-forget and drops messages with no subscriber (#169 open); worse, **clip-ready and
   rank-change events are never emitted at all** — only the five monitor lifecycle kinds fire.
   A landed clip reaches users only when the frontend happens to re-poll. Meanwhile the
   Composer header and `observability.md` still promise an outbox self-heal that the 2026-08-04
   JetStream decision permanently killed.

Beyond these, the docs are badly drifted on the central question of *what exists*: `roadmap.md`
is frozen at 2026-07-18 and lists the shipped V-phase as "not shipped, blocking parity"; the
project front-door `CLAUDE.md` still points every session at a closed month-old punch list;
and `operations.md` is a 17-line stub with no Go-stack runbook two days from serving real users.

**Progress (updated 2026-08-13, post-audit).** P0 blockers 1, 3, and 5 shipped
— heartbeat unified across all four long activities (P0-1/P0-2, `decisions.md`
2026-08-13), the dead `tweet_intent`/`vector` surface dropped (P0-4), and the
fleet reaper + running-only cap + shared-service fallback landed (P0-5,
`decisions.md` 2026-08-13). **P0-3 (schema-migration runner) is the remaining
cutover blocker** — pairs with the pending DB rebuild that clears the stale
`share_state` enum + `video_shares_check` constraint drift. P1s (ingest
partial-refresh wipe, surfacing push path) and the doc restructure remain open.
