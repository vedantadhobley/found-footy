# found-footy as-built audit — 2026-08-05

**Run**: 2026-08-05 (multi-agent workflow, 12 agents, ~15 min, 0 errors)
**Scope**: as-built Go rebuild (`rebuild/go`) — Go LOGIC vs Python LOGIC (code-to-code, not vs the stale Python docs) + doc accuracy across all ten subsystems. Aug 13/14 fresh-La-Liga launch readiness.
**Method**: one finding-agent per subsystem read the shipped Go + its Python counterpart + the relevant design/as-built docs, classified each divergence (improvement / gap / neutral) and each doc claim (high / medium / low inaccuracy); a synthesis agent merged the ten reports. The "test" placeholder report was discarded.
**Tally**: 10 subsystems (ingest, monitor-debounce, video-download-filter, dedup-quality, vision-validation, persist-shares-ranking, team-aliases-rag, twitter-service, schema-data-model, observability-infra-config) · logic diffs **63 improvement / 30 gap / 21 neutral** · doc findings **24 high / 36 medium / 21 low**.

**Recurring theme across all ten: the Go code is consistently healthier than the Python it replaces; the liability is documentation drift.** Design docs describe superseded topologies/schemas as current, and several as-built ledgers describe shipped code as unbuilt. A smaller set of genuine behavioral gaps exists, and the most severe of those are already tracked as tasks — but a meaningful tail is untracked.

## Prioritized gaps vs Python — what the Go rebuild may be MISSING

Ordered by user-facing severity. Each is tagged **tracked** (a task number appears in the reports) or **untracked** (no task cited — these are the silent ones).

### Tier 1 — user-facing correctness regressions in the shipped pipeline

**1. Quality-blind dedup collapse keeps the worse clip** · dedup-quality + persist-shares-ranking · **tracked #171**
- Why: `collapse()` in `event_pipeline.go` is strictly keep-first — the first candidate to complete becomes the asset and every later duplicate is dropped regardless of resolution/duration/bitrate. If the first arrival is a 480p re-encode and a 1080p clean copy lands later, users keep the 480p. `quality.go` (`IsUpgrade`, `ClipQuality`), `Asset.SupersededBySet`, and the `superseded_by` column are all built and unit-tested but **called nowhere** in the persist path. Python's `_pick_best_video_from_cluster` picked the best member and could replace-and-absorb.
- Fix: wire `IsUpgrade` into `collapse()` (supersede incumbent when the newcomer wins), closing #171. Until then it is a real regression, not a stub.

**2. Persistent unknown-scorer placeholder strands the fixture in `active` forever** · monitor-debounce + schema-data-model · **untracked**
- Why: `FixtureReadyToComplete` blocks completion if any non-removed event has `downstream_triggered=false`. An unknown-scorer placeholder (`debounce_count=0`, `removed=false`, `downstream_triggered=false`) that survives to full-time (scorer never attributed) matches that clause, so the fixture never completes and is never pruned. Python's `complete_fixture_if_ready` explicitly filtered `"None" in event_id` placeholders out of the completion gate. Bites friendlies / data-quality edge cases (the Napoli–Osasuna friendly class).
- Fix: add `AND debounce_count > 0` to the event-settled `NOT EXISTS` clause (or hard-delete lingering `debounce_count=0` placeholders at completion time).

**3. VAR-overturned goals keep serving already-published clips** · schema-data-model · **tracked #172**
- Why: `RegisterEventAbsence` soft-deletes the event (`removed_reason='var'`) and closes pending downstream rows, but does **not** delete the S3/Garage objects or revoke already-minted `video_shares`. Python's `mark_event_removed` hard-deleted the event and immediately purged its S3 videos. Until #172 lands, a VAR-overturned goal whose shares were already surfaced keeps serving those clips.
- Fix: build the destroy pipeline (#172) — Temporal-cancel in-flight discovery + revoke shares + delete Garage objects on hit-zero.

**4. Twitter service cannot self-recover from a full cookie expiry** · twitter-service · **tracked #153 (T/b.5)**
- Why: there is no raw-Firefox manual-login path. The 2026-07-22 experiment confirmed Twitter blocks login through Playwright-instrumented Firefox, so if the shared cookies fully expire the Go service can only report `unauthenticated` and wait for cookies to arrive via the backup file. Python's `_launch_manual_firefox` + `auto_verify_loop` was a self-contained recovery. This is the highest-impact functional gap in the twitter subsystem; mitigated only by cookies currently being healthy.
- Fix: implement the T/b.5 raw-Firefox subprocess re-auth path (#153).

### Tier 2 — coverage / scope / resource-risk gaps (mostly untracked)

**5. Default config under-covers national teams vs stated project scope** · ingest · **untracked**
- Why: the tracked-teams filter is built purely from `TrackedLeagueIDs` (default `39,140,78,135,61,1` = five club leagues + World Cup league 1). National teams are captured only if they appear in a configured tournament league's current-season roster. Python unconditionally unioned a static list of 15 FIFA teams, so friendlies/Nations League/Euros/qualifiers were always kept. Outside a World Cup window the default silently drops the "~15 FIFA national teams" the project's own charter promises.
- Fix: add a static national-team seed to `RefreshTrackedTeamsIfStale`, or document the required tournament league IDs explicitly as a config-doc callout.

**6. Empty tracked-teams set fails OPEN (ingests the whole world)** · ingest · **untracked**
- Why: `FetchFixturesForDay` fails open — if the tracked set is empty (cold start where Step-0 refresh also failed), it returns *every* fixture the vendor returned, all of which are then upserted, given alias placeholders, and run through Wikidata resolution. Python fell back to a bounded 15-team static list on fetch failure. Go's failure mode can flood Postgres with every fixture worldwide and hammer Wikidata for hundreds of unknown teams.
- Fix: at minimum log loudly and cap the fail-open path; ideally fall back to a bounded static seed as Python did.

**7. Retention prune reclaims no object storage** · ingest · **untracked**
- Why: `PruneOldFixtures` → `PruneCompleted` is a pure Postgres DELETE and never touches Garage/S3. Python's `cleanup_old_fixtures` swept each event's `_s3_videos` plus the `{fixture_id}/` prefix. Orphaned Garage blobs accumulate indefinitely unless some other (currently unbuilt/undocumented) path reclaims them.
- Fix: extend prune to delete Garage objects for pruned fixtures, or explicitly document where storage reclamation is intended to live.

**8. Temporal worker has no concurrency caps** · observability-infra-config · **untracked**
- Why: `cmd/worker` constructs the worker with `worker.Options{}` (zero value) → SDK defaults (~1000 concurrent activities). Python set `max_concurrent_activities=30`, `max_concurrent_workflow_tasks=10`. Given this host's explicit memory-budget discipline, unbounded concurrency on video-download/ffmpeg activities is a real OOM risk.
- Fix: thread `MaxConcurrentActivities` / `MaxConcurrentWorkflowTaskExecutionSize` from config.

### Tier 3 — observability / operational regressions (untracked)

**9. Per-match coverage summary + SLO alert dropped** · monitor-debounce · **untracked**
- Why: `emitFixtureCompleted` publishes only `{FixtureID, CompletedAt}`. Python built `_build_match_completion_summary` (coverage_rate, goals_with_zero_videos, top_failure_class, time_to_first_s3_p50, …) and emitted a `match_below_slo` WARNING for tracked-league fixtures finishing below the coverage SLO. Likely blocked on the Go video pipeline's telemetry columns, but flag it so the SLO alert isn't silently lost at cutover.

**10. `error_class` capture is gone and its metric label is dead** · observability-infra-config · **untracked**
- Why: `logging.Err(err)` emits a single `error` field (`err.Error()`), no typed class. The `calls_total{error_class}` metric label reads a field key that `Err()` never emits, so in all production code the label is always empty. Python emitted `error_type` (exception class) as a distinct queryable field plus `error_category`/`retry_eligible`.
- Fix: have `Err()` also emit `error_class` (reflect the concrete type name) — this both restores Loki slicing and makes the existing metric dimension live.

**11. Temporal schedules no longer auto-update on redeploy** · observability-infra-config · **untracked**
- Why: `ensure*Schedule()` calls `Create` and swallows `ErrScheduleAlreadyRunning` — it deliberately never updates an existing schedule. Python's `setup_schedules()` UPDATEd on every startup *specifically* to fix a stale-config bug (a 25s timeout that persisted). Go reintroduces exactly that failure mode: a cron/arg/overlap change in code is silently ignored until an operator manually deletes+recreates.
- Fix: add a reconcile-on-drift path, or document the delete+recreate requirement prominently.

**12. DOM-canary schedule dropped** · observability-infra-config · **untracked**
- Why: Python registered an hourly `DOMCanaryWorkflow` (synthetic Twitter search) that detected X markup/selector changes hours before a live match broke scraping. The Go worker bootstrap registers no canary. Early-warning is lost.

**13. Download-path has no logs or metrics** · video-download-filter · **untracked**
- Why: `syndication.ResolveVideo`/`Download` emit no structured logs and no Prometheus metrics; `DownloadAndStage` has no logger; the metric'd `FetchJSON` is dead (never called by the video path). Reject reasons surface only as a single workflow-level slug. Python emitted rich per-step Loki logs and per-class failure counters — a real match-day forensics regression.
- Fix: wire Instruments into resolve/download, or document ffmpeg+workflow logs as the intended surface and retire the dead `FetchJSON` metric.

**14. Error taxonomy loses `error_category` + `retry_eligible` dashboard dimensions** · observability-infra-config · **untracked**
- Why: Go's per-adapter sentinel errors + `errors.Is` are idiomatic and worth keeping, but Python's unified `FootyError` fed `category` and `retry_eligible` to Grafana. Combined with #10, Go's error-observability surface is narrower. Decide before cutover whether those dimensions are wanted.

### Tier 4 — soft-signal / minority / theoretical (mixed tracking)

- **Popularity undercount on pending-clip collapse** · dedup-quality + persist-shares · #171-adjacent — a duplicate matching a still-`pending` (pre-vision) winner deletes staging but never `BumpPopularity`, so the most-reposted clips under-report source count; the `+1` UPDATE is also non-idempotent (retry over-counts). Soft ranking signal, small blast radius. Fix with a deferred-bump.
- **Category-scoped dedup lost (verified vs unverified pools)** · persist-shares · untracked — dedup runs before vision, so verification status is unknown at collapse; two perceptually-similar clips of two *different* goals in the same match could collapse. Only bites on a frame-hash false positive.
- **Per-event `score_after` / scoring-side not stored** · schema · untracked — the `events` table has no score snapshot; `score_after` can't be reconstructed post-hoc. If the frontend surfaces "made it 2-1", capture it at detect time.
- **Cookieless CDN fetch 403s on amplify/promoted clips** · video-download · acknowledged in code — Python attached cookies. Minority of clips; track it.
- **Debounce sub-threshold fragility** · monitor · deliberate + documented (decisions.md 2026-07-07) — a count-1 freshly-detected goal that the vendor drops for a single cycle goes 1→0 and is permanently soft-deleted as `var`. Sharper than the doc's "chips away at durability" framing.
- **Perceptual dedup doesn't span workflow runs** · persist-shares · low — `frame_hashes` are persisted but never queried; a re-spawn inserts a near-dupe. Event re-spawn is rare.
- **Dropped pre-download short-edge gate / no min-file-size floor** · video-download · low — wasted bandwidth on sub-600px clips and a small-but-parseable error body could slip past `ffprobe`. Identical final verdict, just later.
- **Vision expected-minute clamp / missing-API-minute guard** · vision · minor/theoretical — the clamp drops Python's `elapsed−2` acceptance; `APIElapsed==0` rejects a clock-bearing clip Python kept as unverified. Only bites if a 0 minute reaches the activity.
- **Dropped-frame index shift** · dedup · near-impossible in practice — `HashVideo` `continue`s past an undecodable PNG, shifting indices; `ffmpeg fps=` emits all-or-nothing so a `png.Decode` failure is near-impossible.
- **Tweet-text truncation splits multibyte runes** · twitter · edge — `truncate` slices by bytes; a non-ASCII tweet at the 200-byte boundary emits a corrupted last char. Make it rune-aware.

## Notable improvements over Python — so doc rewrites explain the better approach

These are `classification: "improvement"` divergences. Grouped thematically; the rewrites should present them as the intended design, not treat them as bugs.

**Correctness fixes (the headline wins)**
- **Vision period-awareness** (vision) — carries `(period, minute)` on both API and clip sides; hard-rejects a confidently-wrong-half clip (a 45+3 H1 clip validating against a 48' H2 goal). Python had no period concept. Tested against WC-2022 boundaries.
- **Frozen-boundary + stoppage recovery** (vision) — recovers a whole class of frozen `90:00`+board clips and `+`-prefixed sub-timers that Python dropped.
- **DB-enforced state↔timestamp invariants** (ingest + schema) — CHECK constraints tie `state` to `activated_at`/`completed_at`; the two-step `Activate→Complete` transition preserves them. Python just routed documents to a Mongo collection.
- **Completion counter resets on a status flip** (schema) — Go re-gates a premature-FT-then-resume; Python's latch stayed "ready".
- **Content-hash dedup** (schema + persist) — full 16-byte md5 + `UNIQUE(event_id, md5)` replaces Python's URL-string equality (which missed the same clip under different URLs).

**Idempotency & retry-safety by design**
- **Reconcile-merge UPSERT** (ingest) — refreshes only API-mutable fields on existing rows, preserving accumulated domain state; safe to retry. Python skipped existing rows entirely.
- **Deterministic asset UUID** (persist) — `uuid.NewSHA1(event_id+md5)` keys the S3 copy, the DB row (ON CONFLICT), and the share-mint guard, so a full activity retry re-copies the same key, inserts no duplicate, never double-mints.
- **Targeted by-ID retry loop** (ingest) — re-requests only missed IDs in-cycle (3 attempts, linear backoff); Python waited 24h.
- **Terminal-vs-retryable reject taxonomy** (video-download) — permanent failures (deleted/geo/no-variant/corrupt) return a nil-error `Rejected` slug that's never retried; only transient ones consume retry budget.

**Determinism**
- **Deterministic alias selection, no LLM** (team-aliases) — ≥2-language token vote + P1449 nicknames + P1549 demonyms replaces Qwen selection; reproducible and test-pinnable, removes the joi dependency and 3-retry timeout failure mode.
- **Rank tiebreak on older `CreatedAt`** (persist + schema) — total order independent of DB row-return order; established shares stay stable, killing the 2026-06-30 duplicate-rank drift class.

**Efficiency & concurrency**
- **Single-decode dense-frame extraction** (video-download + dedup) — one `ffmpeg fps=` subprocess per clip vs Python's one process *per frame*.
- **Inline single-pass md5** (video-download) — `io.MultiWriter` during download vs Python's second full re-read.
- **One multi-image vision call** (vision) — always 1 joi call (clock read from 3 frames) vs Python's 2–3; load-bearing under the 2-concurrent joi cap.
- **Dedup-before-vision ordering** (dedup) — 1 joi call per perceptual cluster instead of N.
- **Tolerant, integer-offset frame matching** (dedup) — `maxGaps` sliding window bridges single-frame drops; uniform-sampling assumption drops Python's O(n⁴) timestamp machinery.
- **Event-driven twitter waits** (twitter) — `WaitForSelector` replaces a guaranteed 5s `sleep` per search; inline auth-verify on the search page saves another ~3–4s; consecutive-already-seen early stop cuts wasted scrolling on late attempts.

**Data-model upgrades**
- **Asset/Share split** (schema + persist) — public `s_<hex>` share id is stable across dedup-merge/re-encode; a partial `UNIQUE(event_id, rank) WHERE state='active'` structurally prevents rank drift.
- **Symmetric single-counter debounce** (monitor + schema) — one atomic `debounce_count` with exactly-one-flip `downstream_triggered` latch, all in one `RETURNING` transaction, vs Python's two arrays.
- **Per-frame `frame_hashes` + workflow-side fuzzy match** (schema) — a per-0.1s dHash sequence tolerates clip offset/trim that a single whole-clip hash cannot.
- **Pluggable downstream-checklist table** (monitor) — `event_downstream_workflows` adds new downstream types with zero schema change; a single query answers "which workflow is stuck?" VAR removal closes in-flight rows in the same tx, preventing a stuck-fixture deadlock.
- **Per-team tracked-teams provenance** (schema) — one row per team with league/season/`refreshed_at`, atomic `Replace` (truncate+copy); enables promotion-relegation and mixed-season reasoning the single-doc `top_flight_cache` couldn't express.

**Alias/RAG recall**
- **11-language alias breadth + P1449/P1549** (team-aliases) — captures Seleção, Les Bleus, Albiceleste, MUFC/PSG that Python's English-only `aliases.en` discarded.
- **Wikipedia CirrusSearch candidate gen + SPARQL P31 verify** (team-aliases) — fixes the OGC-Nice class failure and replaces free-text description substring matching with a structural ontology check; ~2 HTTP calls vs ~10.
- **Venue-city noise removal** (team-aliases) — drops "london" for Arsenal (removes false-positive matches by any London club).

**Fail-fast, lifecycle, taxonomy**
- **Fail-fast config** (observability) — missing connection strings refuse to boot with a classified error; Python defaulted every endpoint to localhost.
- **Typed vocabulary enums** (observability) — compile-time Module/Action with a runtime backstop; Python used arbitrary positional strings.
- **Ordered LIFO shutdown + eager health probes** (observability) — worker drains before pg/nats close within a bounded timeout; Temporal client forces a `CheckHealth` at startup.

**Twitter fleet coordination (net-new)**
- **mtime + fingerprint + atomic cookie model** (twitter) — sha256-deduped, atomic-rename cookie backups; filesystem mtime propagates one VNC re-auth (or any instance's token refresh) to the whole fleet on next call. Genuinely new design, not a port.
